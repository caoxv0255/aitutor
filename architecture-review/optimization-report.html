三、优化详情

3.1 Docker部署完善

优化内容：完整编排 PostgreSQL + Apache AGE + pgvector + Redis + App 服务

优化前：docker-compose.yml 仅包含 app 服务，缺少数据库和扩展编排，部署依赖手动配置。

优化后：完整的三服务编排架构：

  • db 服务：PostgreSQL 15 + Apache AGE 1.5.0 + pgvector 0.7.0，自定义配置文件
  • redis 服务：Redis 7 Alpine 版本，持久化存储
  • app 服务：应用服务，依赖 db 和 redis 健康检查通过后启动

关键配置：

  • 慢查询日志：5秒阈值
  • 连接池参数：max=20, min=2, 30s idle
  • HNSW向量索引：m=16, ef_construction=64
  • 健康检查：应用、数据库、Redis 三层健康检查

3.2 统一日志服务

优化内容：创建 api/core/logger.js 统一日志服务

核心功能：

  • 四级日志级别：DEBUG / INFO / WARN / ERROR
  • 文件轮转：10MB/文件，保留7个文件
  • JSON格式输出：便于日志分析和ELK集成
  • 请求日志中间件：自动记录请求方法、URL、状态码、耗时
  • 审计日志：关键操作记录（登录、组卷、提交考试等）
  • LLM调用监控：记录模型、token数、耗时、成功率

3.3 缓存服务

优化内容：创建 api/utils/cache.js Redis/内存双模式缓存

核心功能：

  • Redis优先模式：配置 REDIS_URL 时使用 Redis
  • 内存回退模式：Redis不可用时自动切换到内存缓存
  • TTL管理：支持默认/短期/长期三种TTL策略
  • 缓存包装器：cacheWrapper 自动处理缓存读写逻辑
  • 模式匹配清除：支持按pattern批量清除缓存

3.4 模块重组

优化内容：建立 api/modules/ 统一业务模块组织

模块划分：

  • tutor/ — 教学推理模块（tutor-agent, learning-loop, knowledge-graph）
  • exam/ — 考试模块（papers, questions, session, generate, pdf）
  • rag/ — 检索增强模块
  • srs/ — 间隔复习模块
  • vision/ — 视觉解析模块
  • analytics/ — 学情分析模块
  • gamification/ — 游戏化模块
  • auth/ — 认证模块

3.5 LLM模型回退机制

优化内容：增强 services/llm.js 多模型回退和成本控制

回退矩阵：

  • qwen-plus → qwen-turbo → deepseek-chat
  • qwen-max → qwen-plus → qwen-turbo
  • qwen-vl-max → qwen-vl-plus

成本控制功能：

  • 每日预算限制（默认100元）
  • Token成本实时计算
  • 预算统计查询接口
  • 预算耗尽自动降级

3.6 API安全加固

优化内容：增强 api/middleware/security.js 安全防护

新增措施：

  • 请求体大小限制：普通接口1MB，拍照接口50MB，批量接口5MB
  • 操作审计日志：登录、注册、组卷、提交考试等关键操作记录
  • XSS检测：模式匹配检测潜在XSS攻击
  • 安全响应头：X-Frame-Options、X-XSS-Protection、CSP等
  • CSRF防护：来源验证白名单

3.7 数据库性能优化

优化内容：添加分区策略和性能配置

分区策略：

  • 按年份分区 exam_questions_partitioned（2019-2026）
  • 默认分区处理异常年份数据
  • 分区表索引优化

性能配置：

  • shared_buffers: 2GB
  • work_mem: 64MB
  • effective_cache_size: 4GB
  • pg_stat_statements: 开启慢查询分析

四、风险评估与回滚机制

4.1 风险评估

风险项等级描述缓解措施
模块重组兼容性 中 路由结构变化可能影响前端调用 保留原有handlers入口，逐步迁移
数据库分区迁移 中 数据迁移过程可能影响服务 创建分区视图，双写验证，逐步切换
LLM回退成本增加 低 频繁回退可能增加调用成本 预算限制自动触发，回退日志监控
Redis依赖 低 Redis故障可能影响缓存 自动回退到内存缓存，服务不受影响

4.2 回滚机制

回滚策略：所有优化均采用增量式部署，支持快速回滚
  • 代码回滚：保留原handlers目录，模块重组采用渐进式迁移，可随时回退到旧路由
  • 配置回滚：数据库分区采用视图方式，可切换回原表查询
  • 服务回滚：Docker Compose支持版本标签，可快速回退到任意版本
  • 数据回滚：数据库初始化脚本采用幂等设计（IF NOT EXISTS），支持重复执行

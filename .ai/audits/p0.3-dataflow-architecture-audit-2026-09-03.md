## 5. The core question you asked

> 一个用户答错的具体 question，在当前系统中到底以哪张表、哪一个 ID、哪一个 API 作为唯一事实来源？

There is **no single canonical fact** for "user X answered question Y wrong at time T" today. Three parallel, weakly-connected sinks exist:

A) **practice_records** (FK-enforced, per-answer fact) — populated by /api/exam/session/submit only. Used by /api/weak-points. **Internal-only, no UI today.**

B) **wrong_questions** (no FK, curatorial subset) — populated by 5 writers; the only user-reachable one is /api/questions POST from exam-mode.js. **Not wired to dashboard photo flow.**

C) **rag_questions** (shared content index, content_hash identity) — populated by /api/vision/parse → rag_questions. **No per-user column. Cannot carry a per-answer fact.**

D) **exam_questions** (canonical question identity) — 0 rows. Could be the future source of truth IF it had rows AND IF practice_records.question_id FK existed (it does) and IF exam/session/submit were wired to UI.

The vision/parse pipeline writes (C) only. Even if we added code to make vision/parse write to (B), (B) lacks FK to (D). (B)'s kp_id is null in all real cases today. (A) and (B) are written together in the SAME transaction in exam-session.js, but only when (A) is triggered by exam answer save.

## 13. The single-question identity question (per your request)

> 一个用户答错的具体 question，在当前系统中到底以哪张表、哪一个 ID、哪一个 API 作为唯一事实来源？

There is NO single canonical identity. Three parallel, weakly-connected sinks coexist:

A) For shared RAG content: rag_questions (content_hash unique, embedding vector)
   - used for: similarity search (searchSimilarQuestions, similar_questions)
   - NOT used for: user weakness or wrong-question tracking

B) For per-user wrong-question collection: wrong_questions
   - PK: id; UK: only primary key
   - FK: NONE (knowledge_point_id, question_id are plain columns)
   - identity: implicit by (user_email, content)
   - created by: POST /api/questions (canonical add endpoint) or
                  exam-session.js (end of practice session) or
                  visionSearchService (batch-parse only) or
                  taskWorker (legacy, 410 Gone path)
   - But: dashboard photo flow does NOT call any of these

C) For per-user exercise facts: practice_records
   - PK: id; UK: only primary key
   - FK: question_id -> exam_questions.id, session_id -> exam_sessions.id
   - identity: implicit by (user_email, question_id, session_id)
   - created ONLY by: exam-session.js:191 (end of practice session save flow)
   - This is what /api/weak-points reads

CONSEQUENCE:
  - The same physical question can exist in rag_questions, wrong_questions, AND
    practice_records, with no enforced relationship.
  - There is no canonical "this user's mistake on question X is fact N" pointer.
  - rag_questions and wrong_questions both have knowledge_point_id (as text), but
    no FK enforcement, and rag_questions does NOT join into the user flow.

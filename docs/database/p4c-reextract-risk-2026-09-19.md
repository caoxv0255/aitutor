## 1. 探针怎么做的

在 **1694 组「表↔题」归属**上模拟「把表格文本从 stem 抽掉」，按机械判据分级：

| 指标 | 定义 |
|---|---|
| coverage | 单元格在 stem 里的命中并集长度 / stem 长度 |
| gap_ratio | 命中块之间的间隙 / 命中并集 → 大 = 与正文交错 |
| stem_left | 抽掉命中并集后 stem 剩余字数 |

分级：`DESTRUCTIVE`（抽掉=删选项 / 抽空题干）· `FLATTENED_BLOCK`（覆盖率 ≥15% 且间隙比 ≤50%）
· `UNCERTAIN`（覆盖率居中或交错）· `INCIDENTAL`（覆盖率 <5%，只是碰巧命中正文短语）
· `NO_HIT_IN_STEM`（不在 stem，细分在 options / analysis / nowhere）

## 3. 人工复核推翻了「字符串手术」

第一版判据把「覆盖率 ≥0 且抽不空」都标成 SAFE，人工复核样例后发现**判据太乐观**：

```
INCIDENTAL  before: …【实验原理】纤维素酶催化纤维素分解为葡萄糖，用葡萄糖的产生速率…
            removed: 颜色深浅程度        ← 只是碰巧命中正文短语, 抽掉=把句子挖个洞
```

更关键的是复核 `FLATTENED_BLOCK` 时暴露的**硬伤** —— 单元格边界在扁平化后已经丢失：

```
before: …采样的点距化的距离（km）0.0111030（远郊农用）铬浓度（mg/kg）0.250.2…
        实际单元格是 0.01 / 1 / 10 / 30, 拼成了 "0.0111030"
after : …采样的点距化的距离（km）0.0111030（远郊       ← 只删掉了能匹配上的片段, 残留碎片
```

`UNCERTAIN` 的 after 文本更直接证明了伤害：

```
before: 下表是某县政府在2002年和2007年如开县长办公会…
after : 下表是某县政府在和如开县长办公会…              ← "2002年和2007年" 被挖成 "在和"
```

**结论**：在现有 stem 上做字符串删除必然是**部分删除**（边界丢失 → 残留碎片），
且会把合法正文一起挖掉。这条路没有安全的子集。

---

## 4. 建议改为「表感知重抽取」

不是改文本，而是**改抽取**：让 `qbx.py` / `02-extract.py` 把 `w:tbl` 当作**整块**处理，
stem 里只留占位符（如 `⟦TABLE:n⟧`），表格内容进 `question_tables`。
这与 TD-005 Phase 3 的「重提取」是同一个模式（`scripts/td-005/phase3-reextract-stems.mjs`），
有现成的回滚与抽样验收套路可复用。

| 做法 | 安全性 | 说明 |
|---|---|---|
| ~~字符串手术（原计划）~~ | ❌ 否证 | 边界丢失 → 部分残留；误删正文 |
| **表感知重抽取** | 待 pilot 验证 | 整块处理，不从已入库文本里删东西 |

**范围建议**：
1. 先在 `FLATTENED_BLOCK` 387 组对应的题里抽 **20–30 题做 pilot**，人工复核「重抽后题干可读、
   答案/解析未丢、选项完整」三条，通过再谈扩大。
2. `option_layout`（63 题 / 75 张表）**单独处理**：表格就是选项，重抽后必须保证
   `options` 仍完整 —— 建议只补资产不动题面（P4-a 已覆盖）。
3. `NO_HIT_IN_STEM` 的 346 组（表格文本在解析里）**不在 P4-c 范围**：题面本来就没被污染。

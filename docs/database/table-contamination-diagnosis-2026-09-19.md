## 1. 根因

`qbx.py` 完全不处理 OOXML `w:tbl`（grep `tbl` 零命中）。表内段落被当成正文段落、
按文档顺序塞进文本流 —— 所以问题**不是「表格没结构化」，而是结构丢失 + 内容串味**。

实证（2018 天津语文，docx 内有 6 张表，其中 4 张是 A-D 选项排版）：

```
表1: ['A．悄（qiāo）无声息','盘垣（huán）','澄澈（chè）']
表2: ['A．深邃','蜿蜒','荒疏']
```
库内该题 options 实测：
```
A = "悄无声息盘垣澄澈深邃"                       ← 表1第1行 + 表2第1格，跨表拼接
D = "偃卧兀立睥睨（2）依次填入…B．幽邃蜿蜒稀疏…"  ← 吞进了第(2)题的表格
```

---

## 2. 判据（全部机械可复现）

| 指标 | 定义 |
|---|---|
| CONTAMINATED | 题的 stem/options/解析/答案 里出现同卷某张表的单元格文本（≥4 字）。**strong** = 命中 ≥2 个单元格或单元格 ≥8 字；**weak** = 只命中 1 个 4–7 字串 |
| SPLIT | 一张表的单元格落在 ≥2 个 `question_id` 里 → 表被拆散分给多题 |
| DROPPED | 整张表的单元格在本卷任何题面/解析/答案里都找不到 → 内容被丢弃 |

**被废弃的判据**：曾用「options 含 `（N）` 且 N ≠ 题号」当串味信号，**不成立** ——
那绝大多数是合法子问编号（G4：7990 题含子问 / 34816 子问实体化）。
串味必须锚定在表格上才能判断，否则是把正常结构误报成缺陷。

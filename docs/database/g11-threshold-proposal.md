### 2.1 唯一硬指标：可渲染性（KaTeX throwOnError）

> ⚠️ 口径修正（自我纠错）：初版用 `strict:'error'` 报「38 条不可编译」——**那是过严计数**。
> `strict:'error'` 是 **lint 级**严格度，会把 `\text{∪}`、中文标点等**实际能渲染**的公式判失败。
> 换成与应用一致的渲染口径后，**真实不可渲染 = 21 条**（差出来的 17 条是误判）。
> 两个口径都保留在 `katex-check.cjs` 里（`ok` = 可渲染 / `ok_strict` = 严格），闸门用前者。

| 结果 | 数量 | 占比 |
|---|---|---|
| 可渲染 | 11018 | **99.81%** |
| **不可渲染（客观缺陷）** | **21** | 0.19% |

21 条的成因分类（实测）：

| 成因 | 例 | 处理 |
|---|---|---|
| 括号/花括号不配对 | `N^{\mathrm{N}^{\mathrm{N}})` | 规则可修 |
| 双下标（数学非法） | `CS_{2}_{(l)}`、`C_{F}^{L}_{AB}` | 规则可修 |
| 非法命令 | `D\!F\/A\!B`（`\/`） | 规则可修 |
| 双反斜杠残留 | `F_{2}\left(...\right)\\left\|MF_{1}\right\|` | 规则可修 |
| `\left(` 无 `\right` | `\left(` | 规则可修 |
| **JSON 外壳混入 latex 列** | `{"latex":"...","reading":"..."}` | 正则抽字段；抽不出**不硬修** |
| 未知命令（VLM 臆造） | `\boxempty` | **不硬修**（语义不明） |

### 2.4 ⚠️ 结构保真度**不能**作为 F2 判据（本提案的关键结论）

我最初用「是否含 `\frac/\sqrt/^/_` 等结构标记」当 F2 判据，得到「60.7% 达标」——
**这是错的，且错得和本项目既往的坑一模一样（布尔式代理指标）**：

| 桶（结构标记口径） | 数量 | 占比 | 复核结论 |
|---|---|---|---|
| 含结构标记 | 6808 | 61.7% | — |
| 无结构·极简 ≤2 字符 | 2138 | 19.4% | **正常**（`MN`、`n`、`a` 本就无结构） |
| 无结构·中短 3–6 字符 | 1556 | 14.1% | **正常**（`x+2y`、`f'(1)=3`） |
| 无结构·长 >6 字符 | 537 | 4.9% | **误判**：`i \cdot z = 1 + 2i`、`f(x) = ax \ln x, x \in (0, +\infty)` 全是合法 LaTeX，只是用了 `\cdot/\ln/\in/\infty/\left` 而我的正则没列 |

⇒ **结构密度只反映「公式复不复杂」，不反映「识别对不对」**。用它判 F2 会把大量正确公式
误判为降级。真正的 F2 判据只能是**与原文比对**。

### 2.3 测量污染教训（两次自我纠错，记录在案）

1. **JSON 外壳冒充公式**：`latex_formulas` 存的是 `["...", "..."]` JSON 数组串。第一版直接
   把它喂 KaTeX，得到「94.28% 可编译」—— 实际测的是 JSON 外壳（KaTeX 把 `[` `"` 当普通字符
   渲染，永远"通过"）。解析 JSON 展开成 11039 条后才是真数字。
2. **结构正则漏项**：见 2.2，漏了 `\cdot/\ln/\in/\infty/\left/\leq/\geq/\times` 等，制造了
   537 条假「降级」。

- **成本**：中（1 个脚本 + 配对验证）；**只有这条路能给出可辩护的 F2**

## 4. 本轮实施中的三次自我纠错（记录在案，避免重蹈）

1. **判据太严当缺陷**：初版用 `strict:'error'` 报 38 条"不可编译"，其中 17 条其实能渲染
   （`\text{∪}` 等 strict 只是 lint 警告）→ 判据换成和应用一致的 `throwOnError` 口径，真实 21 条。
2. **修出"能渲染的垃圾"**：对 `{"latex":"..."` 这类 JSON 外壳行套 `collapse_bs`，把它变成
   字符串可渲染、内容却是 JSON 外壳的东西，还被判成 F2 —— **错资产比缺资产更糟**。
   → 加两道护栏：JSON 包装行抽不出字段就**不许**再套其它规则；复验通过但仍是 JSON 外壳也判失败。
3. **"`{%` 开头"是坏代理**：用它判"JSON 行"命中 16 条，其中大多数是**真公式**
   （`{}^{14}_{6}C + Y` 碳14记法、`{}^{2}_{1}\text{H}` 氘）—— 又是把好数据当坏数据。
   → 判据改成 `^\{\s*"[a-z_]+"\s*:`（必须是 JSON 字段形态）。

另有两个"看起来对其实是错"的实现细节，已写进代码注释：
`re.sub(pat, '\\', s)` 的替换串会被当**模板**解析并抛错（而 `except: continue` 会把它静默吞掉，
表现为"规则未生效"）；判 `)` 是否多余时用 `out[:idx]` 切片会**漏掉 idx 自己**，
导致退化成"末尾补 `}`"，把多余的 `)` 留在公式里。

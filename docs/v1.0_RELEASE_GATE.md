## 自动门禁 (`npm run gate`)

> 段定义与判据以 `scripts/release-gate.sh` 为准 (本表 2026-09-26 对齐, 共 13 段)。

| # | 段 | 做什么 | 失败含义 | 状态 |
|---|----|--------|----------|------|
| 1 | 单元测试 (vitest) | `npx vitest run --reporter=dot`, 以**退出码**为判据 (grep "passed" 会误判, 失败时也输出该字符串) | 服务层/业务逻辑回归被改坏 | ✅ 662 passed / 4 skipped |
| 2 | 前端 contract (mock) | `node tests/contract.test.js`, mock 后端下校验前后端接口约定 | 前端调用约定与后端不一致, 上真后端取不到数据 | ✅ |
| 3 | Backend Contract Test (真后端) | 自起临时实例 `PORT=3999 SKIP_TASK_WORKER=1 node server.js` (独立进程内存限流桶), 再 `BCT_URL=... node tests/backend-contract.test.js`; 端口被占或未就绪**不回退打主实例** | 真实 HTTP 链路/鉴权/限流回归; 打主实例会污染其限流桶 | ✅ |
| 4 | Docker build | `docker compose -f docker-compose.prod.yml build app` (timeout 600s) + `server.js` 直挂 `/api/` 端点数 ≤ 12 | 生产镜像构建不出来; 或新增端点绕过 `api/modules/*` | ✅ |
| 5 | Health check | `curl $BCT_URL/api/health` 必须含 `"dbReady":true` | 后端没起或数据库连不上, 发布即全站不可用 | ✅ |
| 6 | 仓库一致性 (聚合) | `scripts/check-tracked-refs.mjs` (tracked 引用的本地资源必须已入库) + D079 `.dockerignore` 边界 + `deploy/*.conf` 的 `nginx -t` + 硬编码凭据 + 内部自调用不取自请求头 (SSRF) + mastery 标度 + 仓库 schema 与线上一致 + 新树路由/视觉标准 + AI 输出不进 innerHTML | 干净 clone 跑不起来; 部署模板坏了无人发现; 凭据/SSRF/注入类安全回归 | ✅ |
| 7 | 前端行为测试 (jsdom) | `npm run test:frontend` (`tests/frontend/*`) | 共享层 (`ui.js`/`api.js`/`app.css`) 改动悄悄破坏多页的六态机与错误分类 | ✅ |
| 8 | api.js 契约闸门 | `node tests/frontend/api-contract.test.mjs` (170 项) | 所有页面共用的请求层被改坏, 会批量影响页面 | ✅ |
| 9 | SSE 断连检测 | `scripts/check-no-sse-req-close.mjs`: 流式/SSE handler 内禁止 `req.on('close')`, 例外登记在该脚本的 `ALLOW` | Node 22 下请求体被 `express.json` 读完即触发 `req 'close'` → 整条 SSE 流是空的。写法"看起来很对", review 查不出, 必须机械化拦截 | ✅ |
| 10 | GraphRAG settings 字段名 | `scripts/check-graphrag-settings-fields.mjs`: 用 `.venv/bin/python` 从 graphrag 的 pydantic 模型取**真实字段集**(不硬编码), 再真实调用 `indexer.create_settings_yaml()` 生成 settings 比对 —— `completion_models`/`embedding_models`/`vector_store` 出现未知字段即判红; 并校验 `api_base`/`api_key`/`model` 非空 + `vector_size` 为正整数且等于 `GRAPHRAG_EMBEDDING_DIMS`。缺 `.venv` 或 graphrag 导入失败时**判红, 不静默 pass** | `ModelConfig` 设了 `extra="allow"` —— 写错字段名(如把 `api_base` 写成 `base_url`)被**静默吞掉**, LLM/embedding 退回默认 `api.openai.com`; 本机 DNS 指向黑洞 IP → 索引卡死, 表面"配置都在、进程也在"。这类错不报错, review 看不出来, 必须机械拦 | ✅ |
| 11 | 错误回显收口 | `scripts/check-no-err-message-echo.mjs`: acorn 解析后判定错误对象 `message`(err/error/e/…Err/…Error) 是否落在客户端响应体 sink 实参内 (`errorResponse`/`errorJson`/`createErrorResponse`/`legacyReply`/`sendErrorResponse`/`res.json|send|render|end|write`/`res.status(...).json`); 只进日志/状态码判断/抛出/服务层返回的一律放行, 受控校验文案登记该脚本 `ALLOW` (含理由+日期); 扫不到文件或 sink 时判红 (空转防护) | 路由把 `err.message` 直接拼进返回客户端的错误文案, 泄露 SQL 片段/文件路径/上游报错原文。同类写法散布 27+ 处, 人工必漏, 必须机械化 | ✅ |
| 12 | 日志详情收口 | `scripts/check-logger-error-meta.mjs`: acorn 解析后判定 `logger.<m>(…, { error })` 的 meta.error 是否传了**字符串形态** (`X.message`/模板串/`String(e)`/`'…'`/拼接); 传 Error 对象 (`{ error: e }`) 放行, 例外登记该脚本 `ALLOW` (含理由+日期); 扫不到文件或 logger 调用时判红 (空转防护) | `logger.js:70` 按 `meta.error.message`、`:113` 按 `meta.error?.stack` 取详情 —— 传 `e.message`(字符串) 两者皆 undefined, **err.message 静默丢失**, 排障无据。写法"看起来对"、运行不报错, review 查不出, 必须机械拦 | ✅ |
| 13 | 前端 payload ⊆ schema | `scripts/check-essay-payload-schema.mjs` (只针对 `POST /api/essay/analyze`, 单向判据): acorn 解析 `analyzeService.js` 的 `z.object` 字面量取 schema 键 (被 `.safeParse()` 使用的变量), 再扫全前端所有该端点调用点的 `body` 键 (支持分步赋值回代/作用域解析); 前端键 - schema 键 非空 → 判红 (并排打印三集合); computed key/spread/非字面量/解析失败 → 判红列位置; 空扫描 (调用点 0 / schema 键 0) 判红; `.passthrough()`/`.catchall()`/派生 schema 必须暴露 (会让本闸门失效)。**无 ALLOW 通道** | 前端发了 schema 没有的字段 → 被 Zod 默认**静默丢弃** (title_image 事故: `essay_title` 恒「未命名」), mock 单测全绿却线上失效。review 与 mock 都看不出, 必须机械拦 | ✅ |

> 第 3 段与第 5 段依赖后端: 无 `BCT_URL` 时第 5 段直接判红; 调试可用 `SKIP_BCT=1` / `SKIP_DOCKER=1` 跳过第 3/4 段 (pre-commit 门禁即如此), 但**发布前必须跑完整 13 段**。第 10 段依赖 `.venv` (graphrag 3.1.2): 环境缺失时如实判红, 不提供静默跳过 (跳过即等于没校验, 复现该事故)。第 11、12、13 段均为纯静态 AST 判据, 无外部依赖。

# P0.1 Cache Busting Decision (v0.8.0-dev)

## Problem

The F3 frontend tree `ai-tutor-frontend/` uses native ES modules and was never mounted by `server.js`.
Developers hit a browser cache stickiness on edited JS files (5 retries noted by auditors), and the F3 tree was inaccessible without a manual static server.

## Decision (commit 779c9674)

Mount `ai-tutor-frontend/` as `/f3` in dev/staging only, and force `no-cache` on every served HTML/JS/CSS.

```js
// server.js
const serveF3 = process.env.NODE_ENV !== 'production' || process.env.SERVE_F3 === 'true';
if (serveF3) {
  app.use('/f3', express.static('ai-tutor-frontend', {
    setHeaders(res, path) {
      if (path.endsWith('.html') || path.endsWith('.js') || path.endsWith('.css')) {
        res.setHeader('Cache-Control', 'no-cache, no-store, must-revalidate');
        res.setHeader('Pragma', 'no-cache');
        res.setHeader('Expires', '0');
      }
    },
  }));
}
```

Why this is enough:

1. Chromium / Firefox / Safari all revalidate on `Cache-Control: no-cache` (round-trip 304 vs 200).
2. ES module import goes through the normal HTTP cache, so the headers apply.
3. Dev refresh always sees the latest file because the server returns a fresh 200.

## Why we did NOT add a query-string build hash

The original plan was to stamp each page with `<meta name="build-hash">` and rewrite ES module imports to dynamic `import('../index.js?v=' + hash)`. We declined because:

- Static `import` declarations cannot be runtime-interpolated. Rewriting all 10 page entry scripts to dynamic `import()` is invasive.
- The project has no build pipeline (no vite / webpack / rollup). A `Date.now()` fallback breaks HTTP-cache debugging.
- The HTTP `no-cache` header already solves the practical problem. Query-string busting only pays off when paired with long-lived `max-age=31536000` asset caching plus content-hash filenames (a v1.0 production concern).

## Future Upgrade Path (v1.0)

When a real build pipeline arrives (likely vite, given F3 already uses ES modules):

1. Add `vite.config.js` with content-hash filenames (`assets/index-[hash].js`).
2. Switch `/f3` mount to serve `dist/` instead of `ai-tutor-frontend/`.
3. Re-enable long-lived caching (`max-age=31536000, immutable`) for hashed assets.
4. Keep HTML at `no-cache` so deploys are picked up immediately.

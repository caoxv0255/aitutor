## 🔧 关键修复

### hotfix-2026-08-24: ai_trace request_id 索引顺序
**问题**: Phase B 在 `db.js` 中创建 ai_trace 表时包含 `request_id` 列 + 5 个索引（含依赖该列的 `idx_ai_trace_request_id`）。既存库（009 之前无 request_id 列）会立即报"column does not exist"，导致容器无限重启 43 次。  
**修复**: 将 `idx_ai_trace_request_id` 创建从 `CREATE TABLE` 内移到 `ALTER TABLE ADD COLUMN` 之后。

## 🚀 部署信息

### 系统要求
- Node.js 18+（推荐 22）
- PostgreSQL 15+ with pgvector + Apache AGE
- Redis 7+
- 2GB RAM minimum, 4GB recommended

### 环境变量
```bash
DATABASE_URL=postgresql://aitutor:password@localhost:5432/aitutor_db
JWT_SECRET=<至少32字符的强随机密钥>
DASHSCOPE_API_KEY=<阿里云百炼API Key, Phase D4 验证必需>
OLLAMA_URL=http://host.docker.internal:11434  # bge-m3 embedding
PORT=3002
NODE_ENV=production
ALLOWED_ORIGINS=https://aitutor.uibe.online
```

### 启动
```bash
# 一键部署（推荐）
sudo bash deploy/setup-prod.sh

# 或 Docker Compose
docker compose -f docker-compose.prod.yml up -d

# 健康检查
curl http://localhost:3002/api/health
# 期望: {"success":true,"data":{"dbReady":true,...}}
```

### 已知运维注意事项
1. **DASHSCOPE_API_KEY**: ⚠️ 当前测试 key 已失效，需运维提供新 key（影响 OCR 真实功能）
2. **数据库迁移**: 启动时 `db.js` 自动执行 8 个迁移（005-012）+ 4 个 C2（013-016）+ 1 个 011（task_metrics FK）
3. **首次部署**: 需手动执行 `node scripts/ingest-exam-questions.mjs` 灌入题目（已迁移到容器内 `/app/scripts/`）
4. **重置 exam_papers**: 运维可执行 `docker exec aitutor-db-1 psql ... < scripts/sync-papers-from-questions.sql`
